Device telemetry is recorded beside every number, and every run names the node, engine image and vLLM flags it ran on.

GB10 decode is memory-bandwidth bound, so single-stream tok/s is close to a property of the model and the quantisation. The column worth reading is the batched one.

  • 10 clips, 43.567s of audio in 6 voices across 6 English locales (en_AU, en_GB, en_IE, en_IN, en_US, en_ZA), mono 16-bit PCM at 16 kHz. They are committed audio (bench/speech/clips, set say-10 v1), not synthesised per run, because a word error rate is only comparable over the same bytes.

Pooled over words rather than averaged over clips, which is the standard definition and the honest one: a mean of per-clip rates weights a short clip like a long one.
  • That rate folds case, punctuation, ordinal suffixes and number words to digits (normaliser case-punct-numbers-1 v1), so a transcript that wrote "9" where the reference says "nine" is not scored wrong for its spelling. The stricter orthographic rate, case and punctuation only, is 4.6%, and the gap between the two is how much of the error was spelling rather than hearing.
  • Latency is one clip per request, sent one at a time: p50 739.33 ms, p95 961.2 ms over 10 of 10 clips, end to end from wherever the bench ran.
  • Those figures are end to end, and transport_floor_ms is the measured floor: 28.78 ms for a GET /v1/models over the same link, which transcribes nothing. Subtract it to read the engine's own time; a run driven from the node itself would report a floor near zero.
  • Real-time factor is 0.1815 pooled (7.905s of wall over 43.567s of audio), p50 0.1827 and worst 0.2616 per clip. Below 1 means the engine transcribes faster than the clip plays, which is what decides whether a live stream can be kept up with; the wire is in it, so read it against the floor above.
  • One untimed warm-up request came first (clip-01, 1404.58 ms) and its transcript was discarded. An eager-mode speech engine compiles its kernels on the first real transcription, so that cost is recorded here rather than left inside a p50 or a real-time factor a reader takes as steady state. A user meets it once per launch.

How it is measured

Nothing is loaded, unloaded or restarted

Every run is pure inference load against whatever the node was already serving. A benchmark that reloads the model measures the loader, and it takes the node away from whoever was using it.

Token counts come from the server

Prompt sizes are the engine's own usage.prompt_tokens, requested via stream_options.include_usage, never a chars-per-token estimate: a bad guess would shift the whole prefill x-axis invisibly. Generated counts are usage.completion_tokens, never a count of SSE chunks, because under speculative decoding (DSpark, MTP) one chunk can carry several accepted tokens and chunk-counting silently halves the rate.

Prefix caching cannot fake a deep prompt

Every prompt carries a unique nonce at the front, so --enable-prefix-caching has nothing to hit. A nonce at the end would leave the whole prefix cacheable and the depth numbers would be cache hits wearing a costume.

Decode excludes prefill

The decode clock starts at the first content delta, not at request send. Folding TTFT into the rate turns a decode number into an agent-loop number and the two get quoted interchangeably. Tokens emitted by a reasoning parser count as generated tokens, because they cost decode time like any other.

Prefill tok/s is a floor

It is prompt_tokens / TTFT. TTFT includes queueing and scheduling, and the OpenAI-compatible API exposes no engine-internal prefill timing, so the real forward pass is at least this fast and possibly faster.

Telemetry is the peak, not the average

GPU load, memory and temperature are sampled from AINode's /api/nodes while the bench runs, and the peak is reported: the peak is what the node had to survive. A tok/s number without the load context beside it is not evidence.

"Not measured" is a real answer

A section that did not run renders as those words. Nothing on this page is extrapolated, rounded up from a similar model, or carried over from another run.
