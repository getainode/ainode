# AINode

[Site](https://ainode.dev) · [Docs](https://docs.ainode.dev) · [API routes](ainode/api/server.py) · [Release notes](CHANGELOG.md)

AINode turns a model and an NVIDIA GPU into a local inference API and browser workspace for chat and fine-tuning.
It is for developers and operators who manage their own Linux GPU machines, alone or in a cluster.
This repository contains the orchestrator, dashboard, installer, catalog recipes, benchmarks and tests; model engines run in separate containers.

These are historical measurements on the hardware and software named in each linked run, not promises for another GPU or this source snapshot.

## Versions and requirements

| Component | Value or artifact | Source | Caveat |
|---|---|---|---|
| Source package | 0.5.33 | [Package metadata](pyproject.toml) | A source snapshot, not a new image release. |
| Python | >=3.10; app image uses 3.12 | [Metadata](pyproject.toml), [Dockerfile](scripts/Dockerfile.ainode) | GPU engines and training dependencies run separately. |
| App image | `ghcr.io/getainode/ainode:<version>` | [Installer](scripts/install.sh) | Existing images may predate this source; package availability must be checked separately. |
| Engine | Per-model image and flags | [Catalog](ainode/models/registry.py) | Default image targets GB10; other architectures need a compatible recipe. |
| Platform | Linux, Docker, NVIDIA Container Toolkit and compatible GPU driver | [Installer](scripts/install.sh), [engine backend](ainode/engine/backends/nvidia.py) | No universal GPU memory or performance guarantee. |
| Training and quantization | `ghcr.io/getainode/ainode-train:<version>` or explicit local image | [Job image resolver](ainode/training/engine.py) | Requires an available compatible job image; not built by this repository's public CI. |

## Quick start

For a checkout-only preview, install Python from the requirements table and run from the repository root:

```sh
python3 -m venv .venv
. .venv/bin/activate
pip install -e ".[dev]"
preview_dir="$(mktemp -d "$PWD/.ainode-preview.XXXXXX")"
AINODE_HOME="$preview_dir" scripts/install.sh --dry-run
# Inspect the rendered files, then remove this preview directory.
rm -rf -- "$preview_dir"
```

The preview renders config, service units and a wrapper into the temporary directory and prints their locations without installing a service.
The rendered config and auth files contain newly generated scratch credentials; remove the preview directory after inspection and remove `.venv` when finished.
For an actual GPU node, install Docker and NVIDIA Container Toolkit, then inspect and run the installer:

```sh
curl -fsSL https://ainode.dev/install -o install-ainode.sh
less install-ainode.sh
bash install-ainode.sh
```

A fresh install requires an API key and prints it once; an update preserves existing access control.
Open `http://<node>:3000`, enter the key, pick a compatible catalog recipe and launch it, then send a chat message.
A successful launch shows a running instance and a streamed reply; model loading depends on available disk, memory and the selected engine.
There is no onboarding wizard: the installer starts with no model loaded.
Probe the running service without a credential:

```sh
curl -fsS http://localhost:3000/api/health
```

The response is JSON carrying the service health and version; this does not prove a model is loaded.
Use `ainode doctor` for diagnostics, `ainode update` for upgrades and inspect [the uninstaller](scripts/uninstall.sh) before removing an installation.
`argentaios/ainode` is a retired Docker Hub repository; use GHCR instead.

## Configuration and controls

Settings live under `~/.ainode`; use the dashboard or CLI and [configuration source](ainode/core/config.py) to inspect the full schema.

| Setting | Default | Allowed values and effect | Restart or caveat | Source |
|---|---|---|---|---|
| `web_port` | 3000 (TCP) | Valid port; dashboard and AINode API listener | Restart | [Config](ainode/core/config.py) |
| `discovery_port` | 5679 (UDP) | Valid port; peer discovery | Restart; matching cluster identity and secret required | [Config](ainode/core/config.py) |
| `engine_backend` | `nvidia` | `nvidia` or opt-in `eugr` | Applies on engine launch | [Backend selection](ainode/core/config.py) |
| `gpu_memory_utilization` | 0.5 in code, 0.6 from installer | Fraction accepted by engine; memory reserved per load | Relaunch the model; leave host memory available | [Config](ainode/core/config.py), [installer](scripts/install.sh) |
| `trust_remote_code` | `false` | Boolean; permits model-supplied engine code | Host authority required for overrides; review the model | [Launch controls](ainode/engine/launch_validation.py) |
| `allowed_mount_roots` | Empty list beyond model/dataset stores | Operator-selected absolute roots for extra mounts | Local operator policy | [Config](ainode/core/config.py) |
| API authentication | Required by fresh installer | `ainode auth enable` / `disable`; `AINODE_AUTH=off` opts out at install | Live; updates preserve installed access | [Auth store](ainode/auth/__init__.py), [installer](scripts/install.sh) |
| TLS | Disabled | `ainode tls enable` or `ainode tls enable --tailscale` | Restart; HTTP listener remains available | [TLS](ainode/tls/certs.py) |

People use accounts; programs present keys. Create the first administrator on the installed node with `ainode auth user add <name> --admin`.
For automation, create a restricted decision key with `ainode auth key create --name decision-client --scope decide` and keep it outside source control.
Present it as `Authorization: Bearer <key>`; that scope permits only `POST /v1/decide` and `GET /api/health`.
See [sign-in guidance](https://docs.ainode.dev/security/sign-in) and [local deployment controls](docs/OPERATIONS.md).

The static shell and `/static/*` are public, as are `/api/health`, `/api/auth/status`, `/api/auth/me`, `/api/auth/login` and `/api/cluster/endpoint`.
`POST /api/cluster/join` takes a single-use expiring join token instead of an API key.
The [auth middleware](ainode/auth/middleware.py) is authoritative for method and scope checks.

On the master, `ainode cluster token` prints a join instruction; use `ainode join HOST[:PORT] --token-stdin` for automation.
The legacy interactive spelling is `ainode join HOST[:PORT] TOKEN`; tokens in argv are unsuitable for scripts.
The installer also accepts `AINODE_JOIN=` as a legacy interactive input; never log its value.
Independent installs generate different secrets and are invisible to each other until joined; do not copy `AINODE_CLUSTER_SECRET` into public examples or source.

## Running in production

Deploy an orchestrator container per node, with a separate engine container per loaded model.
Use the [operations checklist](docs/OPERATIONS.md) for network access, authentication, TLS, secrets, limits, monitoring, backups and rollback.
Keep management and engine ports on networks you control; this snapshot does not establish readiness for arbitrary public traffic.

## Tests

With the editable dev installation from the quick start, run from the repository root:

```sh
python -m pytest tests/ -q
```

Also run `ruff check ainode tests` and `python3 scripts/render-bench-table.py --check` before proposing a change.
GPU-marked tests skip when their hardware or optional training dependencies are unavailable; browser-script checks also need Node.js.
These checks do not validate live GPU performance, model quality, image publication or production networking.
Public workflows are intentionally absent and Actions must remain disabled. Workflow-contract tests accept a missing named publication workflow only when no `.github/workflows/*.yml` or `*.yaml` files exist; synthetic counterexamples check both extensions.
When the relevant workflow exists, its original publication checks still apply. Speech checks also retain the catalog image and Dockerfile base-tag assertions; they do not prove live registry availability.
The suite has 30 known baseline failures from the prior qualification, separate from these workflow checks; no all-green claim is made.
Contribute from a fork on a `fable/*` branch and open a pull request.
